1. The idea

Every folder holding an index.html is an agent: its index.html is the agent's report, its results and write-up in HTML (plans: <folder>/plan_*.html). DirAI serves the folder they live in (the tree) and lists every agent on one agent list. When you open an agent's index.html as its owner, a chat panel appears. Each message you send there starts a background claude -p run inside that agent's folder.

1. Message"Rerun the fit with 2× the events and update the plot."
2. Claude worksIn the agent's folder: edits index.html, runs scripts, submits jobs.
3. Reply + highlightsAnswer in the thread; changed parts of index.html are highlighted.
4. Jobs finishDirAI watches the SLURM queue and wakes the agent to update index.html.

A tree can be a git repo, or any folder, such as ~/work holding several repos. Each tree runs its own small server on its own port.

2. Install (once per machine)

You need Python 3.6+, git, curl and Claude Code (~/.local/bin/claude, or set DIRAI_CLAUDE_CMD to its path). Clone DirAI anywhere and put its command on your PATH:

git clone git@github.com:wang2366/DirAI.git ~/work/DirAI     # any location works
ln -sfn ~/work/DirAI/bin/DirAI ~/.local/bin/DirAI          # any folder on your PATH

To update later: git -C ~/work/DirAI pull, then DirAI restart in each running tree. (Coming from a version before 2026-10, use DirAI stop && DirAI start once instead: the checkout's files moved.)

3. Set up a tree

cd ~/work            # a repo (anywhere inside it), or the top of any folder
DirAI init           # once: picks a free port, writes www/dirai.json
DirAI start          # starts the server and waits until it answers

init creates www/ in the tree for DirAI's own files (the agent list, chat threads, caches, logs). In a git repo it also adds those files to .gitignore and adds the line @~/.config/dirai/AGENT_RULE.md to CLAUDE.md, so your own Claude sessions in the repo follow the agent rules too. Outside git it asks before touching CLAUDE.md, since that file would apply to every project below.

Afterwards, every DirAI command works from any folder below the tree: it finds the nearest www/dirai.json above you. Or point at a tree from anywhere with DirAI -C ~/work status.

Refused on purpose: init won't serve / or your home folder, and start won't run a tree that overlaps a running one (e.g. ~/work and ~/work/projA), because both would serve, and edit, the same agents.

4. Open it in the browser

Log in once per browser. This sets a cookie (valid for a year) that marks you as the owner, then shows the agent list:

PORT=$(python3 -c 'import json; print(json.load(open("www/dirai.json"))["port"])')   # in the tree
open "http://127.0.0.1:$PORT/_review/login?key=$(cat ~/.config/dirai/key)"

After that, bookmark http://127.0.0.1:<port>/www/index.html.

Why 127.0.0.1 and a key? The server is reachable from your network, but anyone else only gets the index.html files, read-only. The panel, which runs Claude with your account and files, needs both a connection from this machine and the secret cookie. On a shared cluster node, other users can reach 127.0.0.1 too; the key is what proves it's you.

One command for all of it

A shell function for ~/.zshrc (or ~/.bashrc) that links the command, sets up the tree the first time, (re)starts the server and opens the list logged in:

dirai-up() {
  local tree=~/work
  ln -sfn ~/work/DirAI/bin/DirAI ~/.local/bin/DirAI
  [[ -s $tree/www/dirai.json ]] || DirAI -C "$tree" init || return
  DirAI -C "$tree" restart >/dev/null 2>&1 || DirAI -C "$tree" start || return
  local port
  port=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["port"])' "$tree/www/dirai.json") || return
  open "http://127.0.0.1:$port/_review/login?key=$(cat ~/.config/dirai/key)"
}

5. The agent list

/www/index.html lists every agent in the tree, newest first, with each folder's size and the Claude tokens spent in it. As the owner you also see each agent's chat status (working, unread, read, closed), your Claude plan usage in the header, the serving machine's CPU and memory (and how much of it DirAI and its agents' runs use), and the New agent button. The list is rebuilt every 10 minutes and whenever a new agent is created; DirAI build rebuilds it now.

The scan skips .git, node_modules, virtualenvs, caches and other trees' www/ folders. Add your own with "exclude" in dirai.json.

6. The agent's panel

Open any agent's index.html and click Agent (bottom right). Type a message and press Send. The panel shows the thread; the reply arrives when the run ends. While there is something to show, index.html also gets a status bar at the top: what the agent is working on and your SLURM jobs running there. With neither, there is no bar; the summary card's Open field says what is unfinished.

ControlWhat it does
Ask the agent about thisSelect text in index.html and click it: your message is sent with that passage (and its heading) attached, so you can say "this number looks wrong".
Model pickerModel for this agent's next messages. Sonnet (default) uses less of your Claude limit than Opus; the local gpt-oss models (via Ollama) use none but are slower.
Hide changesParts of index.html the latest run added or changed are highlighted; this toggles that.
Mark read / TaskDoneClear the unread badge / close the thread. A new message reopens it.
CompactSummarize the conversation (Claude Code /compact) when the context gets large; the session continues with fewer tokens per message. The panel warns when it's time.
New chatNext message starts a fresh session that re-reads index.html and the last few messages.
Allow once / Always allowShown when Claude was blocked from something. See access.

Long jobs

Claude submits heavy work with sbatch instead of running it inline, then ends its reply. The agent stays "working" while DirAI checks the queue every 10 minutes (no tokens spent). When the jobs are done, DirAI sends the agent their results so it can update index.html. You can still send messages meanwhile; at most 5 automatic messages run in a row before it waits for you.

Usage limits

New runs pause when Claude's 5-hour or weekly usage reaches its pause level, and resume by themselves. The 5-hour level is 100% unless you drag the marker on its bar of the agent list lower; a paused run resumes after the 5-hour reset. The weekly level has an Auto button, on by default: on day n of the 7-day window the level is n/7 of the limit (14%, 29%, … 100%), so a paused run resumes when the next day starts. Dragging the weekly marker sets the level by hand and turns Auto off. The levels apply to all your trees. A run cut off by the limit is resent automatically, in the same session, once the limit resets.

7. New agent

Click New agent on the agent list (or in any agent), type a folder path relative to the tree (e.g. projA/new_study, with autocomplete) and describe the task, then Create & start. DirAI creates the folder with a starter index.html and hands the task to the new agent, which replaces it with the results.

8. Writing index.html

An agent's index.html is plain HTML, written by you or by the agent. The agent rules (AGENT_RULE.md in the DirAI checkout, given to every agent run):

  • Every index.html starts with a summary card: a collapsible "Summary" with Objective, Inputs, Outputs, Result, Open and Updated (all required; none when nothing applies), plus optional JSON results, between <!-- dirai:card --> markers. The one at the top of this tutorial is an example. After a run that changed index.html the server checks the card, asks the agent once to fix it if needed, and otherwise flags it (card ✗ on the list, a note in the panel). Agents read each other's results through dirai_card.py <folder>, a few lines instead of the whole index.html.
  • Every figure names its plotting script, as a caption with its path relative to the agent's folder, e.g. Script: analysis/plot_rate.sh. Ideally foo.png comes from foo.sh or foo.py.
  • Open items go in the card's Open field: what is unfinished or still running. There is no separate todo.md.
  • Reference images by relative path. The server only serves .html and images (.png .jpg .jpeg .gif .svg .webp); everything else is 404.
  • No "Home" link needed: the server adds one to every index.html.
  • No CSS in index.html. One without a <style> gets the shared index.css from the server; use plain HTML and its classes (.note, .note warn, .tbl, figure + figcaption). Files that keep their own <style> are left as they are.

9. What an agent may do

Runs use claude -p --restricted with an allow list, so nobody needs to approve anything while it runs:

  • Read the agent's own area: its nearest git repo, or its own folder when it isn't in a repo. The tree's top agent sees the whole tree. A parent sees its children; siblings don't see each other.
  • Edit only inside the agent's folder. Delete only through agent_rm.sh, which refuses anything outside it.
  • Git (agents inside a repo): add, commit and push the agent's folder, only when your message asks. Force-push, reset, checkout, rebase, clean, rm -rf and sudo are always blocked.

Letting an agent read another folder

  • Name it in your message: "compare with projB/results". Paths inside the tree that you name (relative, ~/… or absolute) are granted to that agent before the run starts, and logged in the thread.
  • Approve when blocked: the panel lists what was refused; Allow once (this agent) or Always allow retries with it. Folder reads always stay with the one agent, even under "Always allow"; other rules (e.g. a command) then apply to every agent.
  • Every agent, permanently: add the folder to "read_dirs" in dirai.json.
Limit: this confines Claude's own file tools and simple shell commands. A script it runs (python3 x.py) can still read whatever your user can.

10. On a cluster

Start the tree on your devnode (DirAI start), another node (DirAI start NODE), or as its own batch job (DirAI start --job; add account and partition under "slurm" in dirai.json). From your laptop, forward the port and log in through the tunnel:

ssh -N -L 8765:localhost:8765 <you>@<node>
open "http://127.0.0.1:8765/_review/login?key=<contents of ~/.config/dirai/key on the cluster>"

The key lives in your cluster home, so it differs from your laptop's.

Port clashes: a tunnel occupies that port on your laptop. Give a local tree a different port (DirAI init picks one that's free; start refuses a taken one).

11. Settings (www/dirai.json)

Per tree, local to this checkout, never committed:

{"port": 8775,
 "title": "My Work",
 "read_dirs": ["/data/shared"],
 "allow": ["Bash(~/tools/run.sh:*)"],
 "slurm": ["-A", "mygroup", "-p", "cpu"],
 "exclude": ["data", "projA/build"]}
KeyMeaning
portThis tree's server port. After changing it: DirAI stop, then DirAI start.
titleHeading of the agent list (default: the folder's name).
read_dirsExtra folders every agent may read.
allowExtra Claude Code permission rules for the agents.
slurmExtra sbatch options for DirAI start --job.
excludeFolders the agent list skips: a name skips it anywhere, a path with a slash skips that one folder.

Per user, in ~/.config/dirai/: the owner key, the "Always allow" rules (permissions.json), the list of trees (trees) and the AGENT_RULE.md link.

12. Command reference

CommandDoes
DirAI initSet up the tree: port, www/dirai.json; in git, .gitignore and CLAUDE.md lines.
DirAI start [NODE | --job]Start the server here, on NODE, or as a SLURM job.
DirAI statusNode, URL, start time, job time left, and whether it answers.
DirAI restartReload with the current DirAI code, same node and port.
DirAI stopStop the server (and its job, if it has one).
DirAI buildRebuild the agent list now.
DirAI publish [-n]Git trees only: publish committed *.html and an agent list (no sizes or token counts) to the gh-pages branch (-n: dry run).
DirAI listEvery tree you've started, up or down, with port and node.
DirAI -C DIR <cmd>Act on the tree holding DIR.

13. Troubleshooting

SymptomCause and fix
No panel on an agent's index.htmlNot logged in, or opened via the machine name instead of 127.0.0.1. Use the login URL from step 4.
Login URL gives 404Wrong key, or the port reaches a different server, e.g. an SSH tunnel. Check lsof -nP -iTCP:<port> -sTCP:LISTEN; change "port" if something else holds it.
"No DirAI tree here or above"Run DirAI init at the folder you want to serve, or use -C.
"Port … is already taken"Another program listens there. Pick another "port" in www/dirai.json.
"… overlaps this tree"A tree inside or above this one is running. Stop it first, or serve only one of them.
Server not answeringRead www/serve_node.log in the tree, then DirAI restart.
Claude replies it was blockedUse Allow once in the panel, or name the folder in your next message. "Always blocked" items can only be run by you.
An agent shows "queued"Claude usage limit reached; it resumes after the reset shown.
